# REVIEW.md

I read the starter the way I'd read a teammate's pull request: first the helpers (because everything leans on them), then each endpoint, then the things that are missing altogether. Line numbers refer to the original starter file. Everything below is fixed in `app/main.py`.

| # | Where (function / line) | What is wrong | How you'd notice it | How I fixed it |
|---|---|---|---|---|
| 1 | `compute_late_minutes`, L33-37 | It works on the raw UTC datetime and pins the shift start to the *UTC* date, so IST shift times are compared with UTC clocks. Overnight shifts are not handled at all. | Sample 2: a 10:05 IST punch-in is stored as 04:35Z; the function compares it with 09:30 *UTC* and returns 0 instead of 35. | Convert to IST, build the shift start for the record's attendance date (R1, overnight aware), compare against that. |
| 2 | `compute_late_minutes`, L36-37 | `int(seconds / 60) > 10` tests whole minutes, not "strictly more than 10:00". ## Looked at and decided it was fine

- `load_dotenv()` at import: by default it does **not** override variables already set in the environment, so real env vars win, which is what the brief asks for.
- Plain `def` endpoints with a synchronous PyMongo client: FastAPI runs them in a thread pool and `MongoClient` is thread-safe, so parallel requests are fine. Switching to Motor would not buy correctness here.
- The default `mongodb://localhost:27017` fallback: only used when `MONGO_URI` is not set; nothing real is hard-coded. I kept it for local runs.
- `doc.pop("_id")` after `insert_one`: correct, the driver adds `_id` to the dict. I replaced it anyway with the serializer.
- `PunchInIn` ignoring unknown fields: this is what the contract wants for derived fields a client might send.
- In `compute_late_minutes`, returning minutes since *shift start* (not since the end of the grace period) is exactly what R2 says; only the boundary check was wrong.
